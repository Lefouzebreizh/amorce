## Source et périmètre

Base inspectée : `Lefouzebreizh/amorce`, commit `83db34c91d6aa9ebe12c503f50407c7fec8270de`.
La route existante `src/app/phare/page.tsx` est une vitrine. Elle ne contient ni
gestion de projets ni atelier d’écriture. Le titre est défini dans son layout.
Le prototype HTML joint est distinct de cette route. Les deux exemplaires de
la cartographie joints ont le même contenu.

Cette tranche ajoute `/phare/atelier` dans la même application Next.js, sans
remplacer la vitrine ni réutiliser la persistance des montages vidéo d’Amorce.
Le format de données du pilote textuel est indépendant : pas de migration des
projets vidéo et aucune connexion à un compte externe.

## Ce que le pilote fait

- Trois dossiers initiaux **vides** : Le Phare, Ça va, Les coups de mou.
- Création d’autres projets, intention, prochain pas et recherche par mots,
  avec accents facultatifs, dans le projet sélectionné.
- Ajout explicite de textes : origine (mes mots, source, proposition IA),
  provenance précise et section (idée, couplet, refrain, pont).
- Originaux conservés ; une réécriture crée une nouvelle entrée liée à son
  parent, dans le même projet. Choix à travailler, retenu ou écarté.
- Sauvegarde après chaque action validée dans `localStorage`, clé dédiée
  `le-phare-atelier-v1`. Enregistrer les formulaires avant de changer de projet.
- Export JSON de tout l’atelier et Markdown des textes retenus avec provenance.
- Restauration additive : projets copiés avec de nouveaux identifiants, sans
  écrasement. Format, taille et liens entre versions contrôlés avant écriture.
- Effacement explicite d’un projet et annulation de la dernière action tant
  que la page reste ouverte. Au moins un projet doit rester présent.
- Échec d’écriture signalé sans annoncer de sauvegarde réussie. Données locales
  illisibles préservées. Modification par un autre onglet : écritures bloquées,
  export encore disponible, rechargement demandé.

L’origine est déclarative : elle ne prouve pas l’auteur ni les droits. La
sélection « proposition IA » permet de classer un texte apporté manuellement,
elle ne lance aucun modèle. Les données ne sont pas chiffrées par ce pilote et
sont accessibles aux autres scripts exécutés sur la même origine. Aucun compte
ou contrôle d’accès n’est ajouté ; `noindex` n’est pas une protection privée.

## Démonstration reproductible

```sh
npm ci --cache /tmp/amorce-npm-cache
npm run dev
```

Ouvrir `http://localhost:3000/phare/atelier`.

1. Dans Le Phare, écrire une intention et enregistrer le cap.
2. Ajouter une phrase, « Mes mots », une provenance et une section.
3. Retenir la version, puis ouvrir « Écrire une variante » et la conserver.
4. Ouvrir Ça va : aucun texte de l’autre morceau ne doit apparaître.
5. Revenir au Phare, recharger : les deux versions sont présentes.
6. Exporter le JSON, restaurer ce fichier : trois copies séparées apparaissent.
7. Annuler : les copies disparaissent, les trois projets restent intacts.
8. Tester un fichier JSON invalide : les données présentes restent conservées.

## Contrôles de cette session

- `npm test` : **355 tests passent**, dont quatre nouveaux tests du modèle.
- `npx tsc --noEmit` : passe.
- ESLint ciblé sur les fichiers ajoutés : passe.
- `npm run build` : passe, la route `/phare/atelier` est pré-rendue. Le
  prébuild signale que le modèle MediaPipe du studio est injoignable ; ce
  téléchargement existant n’est pas utilisé par l’atelier textuel.
- Chromium réel en 390 × 844 et 1440 × 1000 : vues inspectées, aucun débordement
  mobile ni exception JavaScript dans les parcours exercés.
- Parcours exercés : intention, ajout de texte, variante, statut, séparation
  des morceaux, reprise après rechargement, recherche, export JSON, import,
  annulation, import invalide et blocage entre deux onglets.
- Pas d’essai sur téléphone physique ni avec lecteur d’écran ; ne pas présenter
  ces vérifications comme réalisées. Aucun fournisseur IA appelé.
